
# Telemax 3.5.2
This is AI assisted project that can be hosted on VPS to monitor your personal MAX account and forward messages to Telegram with feedback option.
Telemax 3.5.2 — крупное обновление надёжности MAX ↔ Telegram bridge с упором на сохранность сообщений, работу с вложениями, диагностику ошибок и эксплуатацию в production.

Версия сохраняет существующие Telegram topics и MAX session при корректном обновлении, добавляет новые административные команды и улучшает обработку ошибок и очередей.

## Основные изменения

### Улучшенная обработка вложений MAX

Добавлена поддержка небинарных типов вложений, которые ранее могли отправлять всю задачу в DLQ:

- `SHARE` — ссылка, заголовок и описание preview
- `CONTROL` — системные/служебные события
- `CONTACT` — контактные данные
- `POLL` — вопрос и варианты ответа
- `CALL` — информация о звонке

Неизвестные типы вложений больше не должны приводить к потере текстовой части сообщения.

Текст сообщения и бинарные файлы обрабатываются раздельно, поэтому ошибка скачивания вложения не блокирует доставку текста.

## Надёжность входящих сообщений MAX

Добавлен файловый persistent inbox между MAX SDK и SQLite.

Полученное сообщение сначала сохраняется на диск и только после этого переносится в основную очередь SQLite. Это уменьшает риск потери сообщений при:

- временных ошибках SQLite
- переполнении основной очереди
- кратковременной недоступности БД
- перезапуске процесса во время обработки

Временные проблемы с SQLite больше не должны приводить к немедленному падению всего сервиса.

## Улучшенная очередь доставки

Добавлена более независимая обработка сообщений между чатами.

- медленные загрузки файлов меньше блокируют другие чаты
- несколько задач могут обрабатываться параллельно
- повторные попытки одной задачи не должны останавливать глобальную очередь
- Telegram rate limiting применяется централизованно
- бесконечные retry ограничены по времени и в конечном итоге переводятся в DLQ

При неопределённом результате отправки задача сохраняется как `uncertain` и не повторяется автоматически, чтобы снизить риск дублей.

## Новый чат из Telegram

Добавлена возможность начать новый личный чат MAX прямо из Telegram General topic.

Примеры:

```text
/chat +79991234567 Иван
```

или:

```text
/chat 123456789 Иван
```

Telemax создаёт или привязывает Telegram topic к соответствующему MAX-чату.

После этого сообщения из созданного topic отправляются собеседнику в MAX.

## Mute / Unmute

Добавлено отключение входящей пересылки для отдельных топиков.

Внутри topic:

```text
/mute
/unmute
```

Из General:

```text
/mute THREAD_ID
/unmute THREAD_ID
/muted
```

Mute влияет только на направление:

```text
MAX → Telegram
```

Отправка Telegram → MAX остаётся доступной.

Состояние mute сохраняется в SQLite и переживает перезапуск сервиса.

## Улучшенная диагностика ошибок

Ошибки доставки теперь содержат больше контекста:

- время исходного сообщения
- адресат
- MAX chat ID
- Telegram thread ID
- отправитель
- номер job
- состояние очереди
- описание ошибки

Для проблемных сообщений сохраняется диагностический JSON на сервере.

Пример:

```text
dumps/errors/job-70.json
```

Это позволяет анализировать оригинальный payload MAX и состояние задачи без необходимости воспроизводить проблему.

## DLQ и восстановление

Поддерживаются состояния:

- `dead`
- `uncertain`

Команды:

```text
/dlq
/retry_dlq
/retry_dlq ID
/retry_dlq ID force
/clear_dlq confirm
```

`uncertain`-задачи требуют явного `force`, поскольку предыдущая отправка могла фактически завершиться успешно.

## Управление топиками

Поддерживаются:

```text
/alias Name
/bind MAX_CHAT_ID
/chat USER_OR_PHONE
/mute
/unmute
/muted
```

Существующие соответствия:

```text
MAX chat ↔ Telegram topic
```

хранятся в SQLite.

## Контроль размера базы

Добавлена очистка устаревших завершённых задач и ограничение хранения истории.

Также предусмотрено офлайн-сжатие SQLite через `VACUUM`.

Активные, ошибочные и неопределённые задачи при автоматической очистке не удаляются.

## Работа с большими файлами

Медиа загружаются с ограничением параллелизма, а не через один глобальный последовательный downloader.

Это снижает вероятность ситуации, когда одно большое видео блокирует доставку сообщений из остальных чатов.

Добавлены проверки:

- максимального размера файла
- свободного места на диске
- общего бюджета media queue
- частично скачанных файлов
- некорректных redirects
- несоответствия `Content-Length`

## Безопасность сетевых загрузок

Усилена защита от SSRF при скачивании MAX media.

Блокируются:

- localhost
- private IPv4/IPv6
- link-local адреса
- reserved ranges
- NAT64 well-known prefix
- дополнительные transition ranges

MAX media по умолчанию скачиваются через проверенный public destination.

Telegram API продолжает использовать настроенный SOCKS5 proxy.

## Контроль доступа Telegram

Поддерживаются отдельные списки:

```json
"TG_ALLOWED_USER_IDS": [],
"TG_ADMIN_USER_IDS": []
```

Обычные разрешённые пользователи могут отправлять сообщения Telegram → MAX.

Администраторы дополнительно могут:

- создавать и привязывать чаты
- менять aliases
- использовать mute/unmute
- управлять DLQ

Сообщения от неразрешённых пользователей игнорируются.

## Systemd и watchdog

Поддерживается:

```ini
Type=notify
WatchdogSec=60
```

Сервис сообщает systemd о готовности и продолжает отправлять watchdog heartbeat во время нормальной работы.

Основные команды Telegram:

## Требования

- Linux
- Python 3.10+
- systemd
- curl
- SQLite
- `maxapi-python==2.4.1`
- SOCKS5 proxy для Telegram API

## Важные замечания

Telemax не гарантирует exactly-once delivery.

Если внешний API принял сообщение, но соединение оборвалось до получения ответа, задача может перейти в состояние `uncertain`. Повтор такой задачи может создать дубликат.

Перед принудительным retry рекомендуется проверить фактическую доставку у получателя.

## Рекомендуемое обновление

Для существующей установки рекомендуется:

1. сохранить старую установку целиком
2. развернуть 3.5.2 в чистом `/home/htpc/telemax`
3. сохранить существующий `session_cache`
4. перенести MAX chat ↔ Telegram topic mappings
5. не переносить старые pending jobs и DLQ
6. запустить тесты и `--check`
7. только после этого переключить systemd

Старую установку рекомендуется сохранить до завершения production testing.
